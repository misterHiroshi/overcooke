# 開発進捗まとめ

オーバークック2風の協力調理ゲームを、Web技術でゼロから作った記録。

- **本番URL**: https://overcooke.togeari.cloud （Basic認証: ID `game` / PW `cooke2027`）
- **GitHub**: https://github.com/misterHiroshi/overcooke （public）
- **設計書**: [DESIGN.md](./DESIGN.md)

## 技術構成

| 層 | 技術 |
|---|---|
| クライアント | Vite + TypeScript + Phaser3 (3.90.0) |
| サーバー | Node.js + Express + Socket.io |
| 通信方式 | サーバー権威モデル（クライアントは入力送信＋描画のみ） |
| インフラ | Hostinger VPS、Docker + Traefik（リバースプロキシ／SSL自動） |

クライアントとサーバーは別コンテナで動き、同一ドメインの別パス（`/socket.io/`）で通信する構成。開発時は `localhost:5173`（クライアント）と `localhost:3001`（サーバー）に分かれている。

## 開発ステップ

### STEP1〜4: 基盤づくり
- Vite + Phaser3 の雛形構築
- 矢印キーでのキャラ移動（1人・ローカル完結）
- 調理設備（食材置き場・まな板・コンロ・皿置き場・提供口・ゴミ箱）の配置と当たり判定
- 「拾う → 切る → 焼く → 皿に盛る → 提供する」の最小フロー実装（トマト1種類のみ）

### STEP5: 注文システム
- 注文が一定間隔で自動発生、制限時間内に提供しないと消滅（減点あり）
- スコア・残り時間・注文一覧をHUD表示
- ゲーム全体の制限時間が来たら終了、5秒後に自動で次のラウンドを開始

### STEP6: マルチプレイ基盤（最大の山場）
- ロジックを丸ごとサーバー側（`GameRoom`クラス）に移植し、20Hzでtick
- クライアントは入力（矢印キー＋Spaceキー）を送るだけ、サーバーから届く状態をそのまま描画するだけの薄い作りに
- 複数ブラウザから同時接続して同じキッチンを共有できることを確認
- 自分のキャラを白枠＋「YOU」ラベルで強調表示
- 持ち物アイコンをキャラの向いてる方向に表示（常に真上ではなく）

### STEP7〜8: 仕上げ・デプロイ
- 2人協力プレイの動作確認（同一キッチン・別キャラ操作・状態同期）
- Hostinger VPSへDockerでデプロイ、Basic認証で限定公開

### STEP9: レシピ拡張
- 食材を4種類に拡張: トマト・レタス（要カット）、肉（要加熱）、パン（そのまま使える）
- レシピ2種類を追加: **サラダ**（トマト＋レタス）、**ハンバーガー**（パン＋肉＋トマト）
- 皿は複数食材を持てるように変更、皿を持って各ステーションを回って集める動線に
- まな板を2台に増設（サラダは2種類カットが必要で、1台だと1人プレイで詰むため）

### STEP10: 見た目強化
- 食材・料理を色付き四角から絵文字表示に変更（🍅🥬🥩🍞、完成品は🥗🍔）
- まな板・コンロに実際のプログレスバー（色付きの帯）を追加

### STEP11: ギミック追加
- **焦げリスク**: 肉を焼いた後、放置すると焦げて（🔥）使えなくなる。バーの色で警告（緑→オレンジ→赤）
- **障害物**: マップ中央に🧱を2箇所配置し、移動に一工夫必要に
- **ベルトコンベア**: 食材や皿を乗せると自動で反対側まで運んでくれる設備

## ハマった問題と解決

- **キー入力が固まる不具合**: Phaser標準の`input.keyboard.createCursorKeys()`が実ブラウザ（Chrome/Mac）でkeyupイベントを稀に取りこぼし、キーが押しっぱなし判定のまま固まる不具合が発生。ヘッドレスブラウザでの自動テストでは再現せず、実機でのみ発生。生のDOM `keydown`/`keyup`イベントを自前で追跡する方式に切り替えて解決。
- **Phaserのバージョン**: 依存関係のインストール時、最新メジャーバージョンのPhaser v4（破壊的変更が多い）が入ってしまっていた時期があり、実績のあるv3系（3.90.0）に固定し直した。
- **サラダが1人で作れない問題**: まな板が1台だと「トマトを切って置いたまま、レタスを取りに行く」動線が成立せず詰んでいた。まな板を2台にして解決。
- **プレイヤーの色が被る不具合**: 接続人数（`players.size`）を基準に色を割り当てていたら、誰かが途中で切断すると番号がズレて2人が同じ色になる不具合が発生。接続ごとに増え続けるカウンターに変更して解決。
- **ゲームが終わったまま動かなくなる**: ゲーム内蔵タイマー（120秒）が切れるとgameOver状態になり全操作が停止する仕様。開発中サーバーを起動しっぱなしにしていると気づかず「キーが反応しない」と誤解しやすかった。終了5秒後に自動で次のラウンドを開始する仕組みを追加して解決。

## 検証方法

すべての機能をPlaywright（ヘッドレスブラウザ）とsocket.io-clientによる自動テストで検証しながら進めた。実際にキーボード入力をシミュレートしてゲームを最後まで進行させ、状態(スコア・注文・持ち物など)を直接アサーションする手法。
